# Piiicker

**Piiicker** — лёгкий локальный сервер для сбора данных с ТСД, смартфонов и сканеров штрихкодов. Работает в локальной сети, без интернета, без облака, без лицензий. Идея — дать малому бизнесу простой и гибкий инструмент вместо дорогих коммерческих ТСД.

Один компьютер (ноутбук руководителя), один запущенный скрипт `server.py` — и все сотрудники с телефонами или сканерами подключаются к нему по Wi-Fi. Всё, что они пикают, попадает в одну базу на компьютере.

---

## Что умеет

- **Пикер** — сотрудники заносят штрихкоды в общий журнал. Каждый пик подписан временем, кодом сотрудника и устройством.
- **Проверки** — второй режим для контроля цен, слотов, остатков. Оператор пикает товар, видит в базе нужное значение и сравнивает с физической реальностью. Найденное расхождение отмечает одной кнопкой.
- **Офлайн-режим** — если Wi-Fi пропал, пики копятся в телефоне и уедут на сервер, как только связь вернётся.
- **Разграничение по сотрудникам** — вход по коду из `employees.csv`.
- **Журнал событий** — все входы, выходы, откаты, обрывы связи и дубликаты пишутся отдельно, для аналитики и разбора инцидентов.

## Как запустить

### 1. Установить Python

Нужен **Python 3.9 или новее**. Скачать: https://www.python.org/downloads/

Никаких сторонних библиотек устанавливать не нужно — всё на стандартной библиотеке.

### 2. Положить все файлы в одну папку

```
server.py
login.html
tsd.html
compare.html
shared.css
employees.csv
catalog.csv
```

`piiicker.db` создастся сам при первом запуске.

### 3. Запустить сервер

В терминале (PowerShell, cmd, bash):

```
python server.py
```

Сервер напечатает что-то вроде:

```
Сотрудников в базе : 3
Строк в каталоге   : 5
Имя (2-й столбец)  : Наименование
Для compare        : Цена, Слот, Остаток
База данных        : C:\Piiicker\piiicker.db

==============================================================
 ССЫЛКА ДЛЯ СОТРУДНИКА:
     http://192.168.1.42:8000/
==============================================================

 СПИСОК СОТРУДНИКОВ (код ; имя):
   31231    ; Jessy Pinkman
   31335    ; Walter White
   57982347 ; Saul Goodman
```

### 4. Раздать сотрудникам

Скопируйте ссылку из блока «ССЫЛКА ДЛЯ СОТРУДНИКА» и отправьте её каждому в мессенджер вместе с его кодом. Сотрудник открывает ссылку в браузере телефона, вводит код — и работает.

**Важно:** телефон и компьютер должны быть в одной Wi-Fi сети. Выход в интернет не нужен.

## Файл `employees.csv` — сотрудники

Разделитель — `;` или `,`. Строки, начинающиеся с `#`, игнорируются.

```csv
# Код ; Имя
31231 ; Jessy Pinkman
31335 ; Walter White
57982347 ; Saul Goodman
```

- **Первый столбец** — код, который сотрудник вводит при входе. Он же используется как ID.
- **Второй столбец** — имя, которое показывается в интерфейсе и пишется в базу.

Если имя пустое — в интерфейсе будет нейтральное «Сотрудник».

---

## Файл `catalog.csv` — каталог товаров и свойств

**Обязательное правило:** первая колонка — **код** (штрихкод товара), вторая колонка — **название**. Всё, что правее, — свободные столбцы, которые увидит оператор в режиме проверок.

Названия колонок в шапке могут быть любыми: для России — `код ; Наименование ; Цена ; Слот`, для Армении — `կոդ ; Անուն ; գին ; տեղ`. Сервер и клиент ориентируются на **позицию**, а не на название.

Пример для магазина:

```csv
код ; Наименование ; Цена ; Слот ; Остаток
1462763682 ; Хайнекен 0.5 стекло ; 189.90 ; A-12 ; 45
2345678901 ; Absolut 0.5 ; 599.00 ; B-04 ; 12
9876543210 ; Coca-Cola 0.5 ПЭТ ; 89.90 ; A-05 ; 120
```

**Что с этим делает каждая страница:**

- **`tsd.html`** — при пике показывает название товара (второй столбец) рядом со штрихкодом. Сотрудник сразу видит, то ли он пикнул.
- **`compare.html`** — показывает название сверху как заголовок карточки, а под ним — значение одного из свободных столбцов. Какого именно — оператор выбирает в меню ☰.

**Свободные столбцы** — это то, что проверяют. Цена, слот хранения, остаток, отдел, дата изготовления — что угодно. Каждый магазин настраивает список под себя. Меняется задача — меняется шапка файла, код остаётся тем же.

**Кодировка файла:** `catalog.csv` можно сохранять и в UTF-8, и в Windows-1251 — сервер читает обе. Excel на русской локали сохраняет в cp1251, это нормально, работает.

## Как работают страницы

### `login.html` — вход

Открывается по адресу `http://<IP>:8000/`. Сотрудник вводит код из `employees.csv`. Если код верный — ставится cookie-сессия и происходит переход в пикер.

### `tsd.html` — Пикер

Основной режим для ревизии, приёмки, пересчёта.

- Пик штрихкода → строка добавляется в журнал.
- Рядом со штрихкодом показывается название товара из каталога (если он там есть).
- Кнопка **↩️ Удалить последнюю** — откат последнего пика этого сотрудника.
- Кнопка **🔢 Цифры** — виртуальная цифровая клавиатура, для случаев, когда нет физического сканера или надо ввести количество.
- Меню **☰** справа сверху — переход в «Проверки» и смена пользователя.

### `compare.html` — Проверки

Второй режим для контроля. Ничего не пишет в лог пиков, вместо этого ведёт свой отдельный журнал проверок.

- Пик штрихкода → на экране появляется карточка:

  ```
  Хайнекен 0.5 стекло     ← название из 2-й колонки каталога
  1462763682              ← штрихкод
  ЦЕНА                    ← выбранный столбец
  189.90                  ← значение из каталога
  ```

- Оператор смотрит на физический ценник (или на слот, или на что надо) и сравнивает.
- **Совпало** — просто пикает следующий товар, карточка обновится.
- **Не совпало** — жмёт **⚠ Не совпадает**. В базу уходит отметка о расхождении.
- **Выбор столбца** — в меню ☰, раздел «Показывать столбец». Список формируется автоматически из свободных столбцов `catalog.csv`. Выбор запоминается на этом ТСД.

Что можно проверять такой схемой:

| Задача | Что в шапке каталога |
|--------|----------------------|
| Проверка ценников | `код ; Наименование ; Цена` |
| Проверка выкладки по слотам | `код ; Наименование ; Слот` |
| Проверка планограммы (отделов) | `код ; Наименование ; Отдел` |
| Проверка остатков | `код ; Наименование ; Остаток` |

Один файл — три задачи. Меняется задача — меняется столбец в меню.

## База данных `piiicker.db`

Вся работа хранится в одном файле SQLite. Открыть можно **DB Browser for SQLite**, **DBeaver**, командой `sqlite3 piiicker.db` или скриптом на Python.

Три таблицы:

| Таблица        | Что хранит |
|----------------|------------|
| `logs`         | Пики — штрихкоды, которые сотрудники реально внесли |
| `compare_logs` | Проверки — что и у чего проверяли, с отметками расхождений |
| `events`       | Всё остальное: входы, откаты, обрывы связи, дубликаты |

### Таблица `logs` — пики

| Столбец         | Тип      | Что значит |
|-----------------|----------|------------|
| `id`            | INTEGER  | Технический номер строки, автоинкремент |
| `pick_time`     | TEXT     | **Время пика на телефоне сотрудника.** `ГГГГ-ММ-ДД ЧЧ:ММ:СС.ммм`. Именно это время «боевое» — когда сотрудник нажал Enter |
| `employee_code` | TEXT     | Код сотрудника |
| `employee_name` | TEXT     | Имя сотрудника на момент пика |
| `value`         | TEXT     | Штрихкод или значение, введённое вручную |
| `display_name`  | TEXT     | Название товара, которое оператор видел на экране в момент пика (из 2-й колонки `catalog.csv`) |

**Уникальность:** комбинация `(pick_time, employee_code, value)` уникальна. Защита от задвоений при обрывах связи: если запись попробует записаться дважды — второй раз отбрасывается, а в `events` появляется `op = duplicate`.

### Таблица `compare_logs` — проверки

| Столбец         | Тип      | Что значит |
|-----------------|----------|------------|
| `id`            | INTEGER  | Технический номер |
| `check_time`    | TEXT     | Время проверки на телефоне |
| `employee_code` | TEXT     | Кто проверял |
| `employee_name` | TEXT     | Имя на момент проверки |
| `device_id`     | TEXT     | Устройство |
| `value`         | TEXT     | Штрихкод, который пикнули |
| `display_name`  | TEXT     | Что оператор видел в карточке (цена, слот, остаток и т.п.) |
| `op`            | TEXT     | `check` — обычная проверка; `mismatch` — оператор отметил расхождение |

### Таблица `events` — журнал событий

| Столбец         | Тип      | Что значит |
|-----------------|----------|------------|
| `id`            | INTEGER  | Технический номер |
| `server_time`   | TEXT     | Время на сервере, когда событие попало в базу |
| `pick_time`     | TEXT     | Время на клиенте, если событие к нему привязано |
| `delay_sec`     | REAL     | Разница `pick_time → server_time` в секундах. Главный индикатор проблем с сетью |
| `employee_code` | TEXT     | Кто |
| `employee_name` | TEXT     | Имя на момент события |
| `device_id`     | TEXT     | Идентификатор устройства, `XXXX-XXXX` |
| `device_info`   | TEXT     | Сжатый `User-Agent`, например `Android/Chrome` |
| `op`            | TEXT     | Тип события (см. ниже) |
| `detail`        | TEXT     | Штрихкод, IP-адрес и т. п. |

### Типы событий (`op`)

| `op`              | Когда пишется | Что в `detail` |
|-------------------|---------------|----------------|
| `auth_ok`         | Успешный вход | IP-адрес |
| `auth_fail`       | Неверный код | IP-адрес |
| `logout`          | Смена пользователя | — |
| `add`             | Новая запись в `logs` | Штрихкод |
| `duplicate`       | Запись уже была | Штрихкод |
| `undo`            | Откат последней записи | Штрихкод |
| `check`           | Проверка в compare | Штрихкод |
| `mismatch`        | Отметка «не совпадает» | Штрихкод |
| `offline_start`   | Телефон потерял связь | — |
| `offline_end`     | Связь восстановилась | — |
| `multi_login`     | Вход с другого устройства | ID предыдущего устройства |
| `bad_time`        | Некорректный формат времени | Что прислал |

## Готовые SQL-запросы для аналитики

Вставлять в DB Browser for SQLite во вкладке «Execute SQL».

### Сколько пиков сделал каждый сотрудник

```sql
SELECT employee_code, employee_name, COUNT(*) AS picks
FROM logs
GROUP BY employee_code
ORDER BY picks DESC;
```

### Средняя задержка по сотрудникам (у кого хуже сеть)

```sql
SELECT employee_code, employee_name,
       ROUND(AVG(delay_sec), 3) AS avg_delay,
       MAX(delay_sec)           AS worst_delay
FROM events
WHERE op = 'add'
GROUP BY employee_code
ORDER BY avg_delay DESC;
```

### Записи, которые «зависли» в очереди дольше 5 секунд

```sql
SELECT server_time, employee_code, employee_name, delay_sec, detail
FROM events
WHERE op = 'add' AND delay_sec > 5
ORDER BY delay_sec DESC;
```

### Сколько раз у кого рвалась связь

```sql
SELECT employee_code, employee_name, COUNT(*) AS breaks
FROM events
WHERE op = 'offline_start'
GROUP BY employee_code
ORDER BY breaks DESC;
```

### Список ценников на перепечатку

```sql
SELECT value, display_name, COUNT(*) AS flagged
FROM compare_logs
WHERE op = 'mismatch'
GROUP BY value
ORDER BY flagged DESC;
```

### Сколько проверил и сколько расхождений нашёл каждый

```sql
SELECT employee_code, employee_name,
       SUM(op = 'check')    AS checked,
       SUM(op = 'mismatch') AS mismatches
FROM compare_logs
GROUP BY employee_code
ORDER BY checked DESC;
```

### Кто и когда делал откаты

```sql
SELECT server_time, employee_code, employee_name, detail
FROM events
WHERE op = 'undo'
ORDER BY server_time DESC;
```

### Подозрительные входы с двух устройств

```sql
SELECT server_time, employee_code, employee_name, device_id, detail
FROM events
WHERE op = 'multi_login'
ORDER BY server_time DESC;
```

### Сводка по всей смене одним запросом

```sql
SELECT op, COUNT(*) AS count
FROM events
GROUP BY op
ORDER BY count DESC;
```

## Экспорт в Excel

Скрипт на Python выгрузит все три таблицы в CSV:

```python
import sqlite3, csv

conn = sqlite3.connect('piiicker.db')
for table in ('logs', 'compare_logs', 'events'):
    cur = conn.execute(f'SELECT * FROM {table}')
    cols = [d[0] for d in cur.description]
    rows = cur.fetchall()
    with open(f'{table}.csv', 'w', newline='', encoding='utf-8-sig') as f:
        w = csv.writer(f, delimiter=';')
        w.writerow(cols)
        w.writerows(rows)
conn.close()
```

Получатся три файла, которые открываются в Excel двойным кликом.

## Резервная копия

`piiicker.db` — это один файл, но во время работы рядом с ним живут ещё два: `piiicker.db-wal` и `piiicker.db-shm` (журналы SQLite).

**Правильный бэкап:**

- Если сервер запущен — копировать все три файла.
- Если сервер выключен — достаточно одного `piiicker.db`.

Не удаляйте `-wal` и `-shm` вручную — потеряете последние записи.

**Про OneDrive:** если рабочая папка внутри OneDrive, изредка возможны ошибки «database is locked» — облако синхронизирует файл в момент записи. Если это мешает, вынесите папку сервера из OneDrive (например в `C:\Piiicker\`).

## Частые вопросы

**С телефона не открывается ссылка.**

1. Телефон и компьютер должны быть в одной Wi-Fi сети (не гостевой).
2. Windows Firewall мог заблокировать Python. При первом запуске система спрашивает разрешение — нужно согласиться. Если пропустили — добавьте правило для `python.exe` в «Разрешить работу с сетью».
3. Некоторые роутеры включают «изоляцию клиентов» — тогда устройства не видят друг друга. Используйте основную сеть.

**У некоторых записей `delay_sec` очень большой (100+, 1000+).**

Это записи, которые лежали в офлайн-очереди. Сотрудник пикал без сети, `pick_time` сохранён правильный, а на сервер запись доехала, когда связь вернулась. Чем больше `delay_sec`, тем дольше не было связи.

**Много событий `duplicate`.**

Тоже признак нестабильной сети: телефон отправил запись, сервер сохранил, но ответ не дошёл. Телефон повторил — сервер отбросил как дубликат. Данные при этом не страдают.

**Как узнать, какой сотрудник работал с какого телефона.**

По столбцу `device_id` в таблице `events`. У одного ТСД он постоянный, пока не почистят данные браузера. `device_info` показывает примерный тип устройства (Android/Chrome, iPhone/Safari и т. п.).

**Файл `catalog.csv` не читается, ошибка про кодировку.**

Сервер пробует UTF-8 и Windows-1251. Если не сработало — значит, файл в другой кодировке. Пересохраните его в UTF-8 (в Excel: «CSV UTF-8»). Либо откройте в VS Code и переключите кодировку в правом нижнем углу.
